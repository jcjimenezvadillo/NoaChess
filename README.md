## UCI Chess Engine in C# (.NET 10)

NoaChess is a modular UCI chess engine written from scratch in C# on .NET 10, with its own WPF board GUI. It follows an incremental, measured development process: every version is validated with unit tests, Perft, automated engine matches and Elo estimation before moving on. Development is AI-assisted; the architecture, the one-term-per-SPRT methodology, the calibrated gauntlets and every accept/cut decision are the author's own.

**Current version: v4.0.0 — BLOCK 12 foundation (no strength change).** The cost model that governed NNUE design was measured for the first time and it was wrong: the L1 dot product is **26.2%** of NNUE work, feature-transformer row traffic is **73.8%** — while the code had asserted for two versions that the dot product was *"THE cost of NNUE eval"*, which is precisely what justified keeping the network narrow. Ships the int8 L1 architecture (evaluation −25%), a king-square accumulator cache (refreshes 40-52× cheaper, 99.6% served), a streaming dataset that removes the 120M-record RAM ceiling, and a provenance gate that turns the v3.2.0 failure into a machine check. The embedded net is unchanged and a fixed-depth suite searches the same 193,746 nodes as before. Also fixed a pre-existing bug that saved checkpoints with no weights whenever the validation split was smaller than one batch. See [CHANGELOG](CHANGELOG.md).

> **🚧 Active campaign: v4.x — NNUE architecture overhaul (branch `4.0.0`).** Five consecutive NNUE generations landed flat, and the cause has been identified: the network is **8× narrower** than reference-class nets (FT 128 vs 1024, one output bucket vs eight) and trained on roughly **100× less data** (13 M positions per generation against billions). The campaign runs **foundation → data → capacity → search**: int8 L1 quantization, an accumulator cache and a streaming training pipeline first; then a 300–500 M position dataset; then width and output buckets; then the search bundle. Expected destination ~3300–3450 CCRL. Full plan in [ROADMAP.md](ROADMAP.md) (BLOCK 12).
>
> **Correction (2026-07-31):** the "human-opening datagen" credited to v3.2.0 **never actually ran** — every dataset manifest on disk records `"openingPlies": "8-9 random legal"`, because the pipeline's `-Book` argument was never passed. The nets are real and the measured ~3080 CCRL stands; what is void is the *provenance claim* and the conclusion drawn from it ("pure self-play is exhausted"), which was measured on a net trained with random openings.

**v3.3.0 — proven-mate stop (strength-neutral, shipped for behaviour).** The iterative-deepening loop now stops once a completed iteration proves a mate within 2 moves — the one case where deepening cannot improve the answer. A mate-in-1 that took **1074 ms now takes 22 ms** (1253 ms → 112 ms at 30 threads), same move and same reported mate; normal positions are untouched and fixed-depth play is byte-identical. SPRT vs v3.2.1: +3.3 ±23.1 over 523 games (neutral, as expected — the game ends before the banked clock can be spent). Also **measured and cut**: rescaling the NNUE eval to "align" it with the classical margin scale lost −61.7 ±20.7 Elo (H0 accepted) — the margins are already calibrated to the compressed net. Strength is unchanged from v3.2.0's gen7 net. See [CHANGELOG](CHANGELOG.md).

**v3.2.1 — bot-stability hot-patch (no strength change).** Caps iteration depth at `MaxPly` so an unlimited ponder search in a repetition position with a warm TT can no longer spin through depths that search nothing (observed: depths 22→26 in 30 ms, burning a core for the opponent's whole think time), and makes a stalled search report `info string search still stopping after Ns` instead of freezing silently. See [CHANGELOG](CHANGELOG.md). Strength is unchanged from v3.2.0, below.

**v3.2.0 — NNUE gen7 (NNUE-0.7) + human-opening datagen pipeline.** Self-play datagen now seeds openings from a human elite book (chess.com >2800 + Lichess elite; 3.04M unique FENs via `pgnbook`) instead of random legal plies. gen7 embedded, promoted as a **marginal** generation: **vs gen5 +3.7 ±10.2 (LOS 76.2%, parity)**, **vs classical +28.5 ±13.0 (LOS 100%)** — the total accumulated NNUE value over the classical eval. ### **Main Features**
- Bitboard board representation with **magic bitboards** for sliding pieces (**PEXT/BMI2** lookup on CPUs where it is fast — Intel and AMD Zen3+ — with an automatic CPUID guard).
- Full legal move generation (castling, en passant, promotions), validated against the public Perft reference values.
- **Search**: iterative deepening, aspiration windows with progressive widening, PVS, transposition table (Zobrist), **staged move generation with lazy legality** (TT move served without generating, then captures, then quiets), quiescence search, null-move pruning, singular extensions, SEE (static exchange evaluation) ordering and pruning, killer/history/counter-move/continuation-history ordering, history-informed logarithmic LMR, reverse futility pruning, futility pruning, late move pruning, Internal Iterative Reductions, ProbCut.
- **Parallel search (Lazy SMP)**: up to 32 worker threads search the same root sharing one lock-free transposition table (benign races, key-verified) and vote on the move; the board, search stack, histories and evaluator accumulators are per-thread. `Threads=1` is byte-identical to the single-threaded search. An SMP-only time-management guard (instability averaged over the pool, soft deadline capped, node-level mid-iteration cap) bounds a ponderhit clock spike.
- **Evaluation**: tapered (middlegame/endgame) evaluation blended by game phase — PeSTO piece values, two-phase piece-square tables, reference-style attack bitboards (attackedBy per piece type + double attacks) feeding a full threat evaluation (hanging pieces, threats by minor/rook/king, safe-pawn and pawn-push threats, restricted pieces, knight/slider threats on the queen), king safety (attack units + pawn shield through quadratic danger curve), non-linear piece mobility (reference lookup tables over a reference-style mobility area, with x-ray attacks and pinned-piece restriction), tempo bonus, knight outposts, space, bishop pair, rooks on open/semi-open files and on the 7th rank, tapered pawn structure (doubled/isolated/passed/backward, phalanx, connected passers, blocked passers, rook behind passer); mop-up term for won endgames.
- **NNUE evaluation**: HalfKAv2_hm neural network (InputSize 22528, kings as features), quantized integer weights, incremental accumulators, AVX2 SIMD inference; trained from self-play datagen with WDL mixing and resign/draw adjudication, refined by generational self-play. Beats the classical evaluator; selectable via UCI `UseNNUE` / `EvalFile` options, with the current net embedded in the executable.
- **Time management**: soft/hard budgets, 85% increment use, conservative ply-adaptive horizon, movestogo support, GUI-latency safety margins.
- **Full UCI**: uci, isready, ucinewgame, setoption (Hash, Threads, MoveOverhead, Profile, UseNNUE, EvalFile), position, go (depth/nodes/movetime/clock/ponder/infinite), stop, quit. Asynchronous search; publishes as a single self-contained .exe.
- Engine profiles (Default/Bullet) with tunable search/time parameters.
- **WPF GUI** (MVVM): play against the engine with vector piece graphics (Cburnett SVG), live evaluation bar and search depth, background analysis on the user's turn.
- Allocation-free hot paths; BenchmarkDotNet benchmark suite.

### **Solution Layout**
```
src/NoaChess.Core      -> pure chess rules: board, bitboards, moves, FEN, Zobrist
src/NoaChess.Engine    -> search, evaluation, heuristics, TT, time management
src/NoaChess.UCI       -> UCI console host (the engine executable for GUIs)
src/NoaChess.GUI.Wpf   -> WPF board application (MVVM)
tests/                 -> xUnit test suites (Perft, make/unmake, search, SEE...)
benchmarks/            -> BenchmarkDotNet micro-benchmarks
```
Dependency rule: `Core` depends on nothing; `Engine` uses `Core`; `UCI` and the GUI are thin hosts. The full plan lives in [ROADMAP.md](ROADMAP.md).

### **Build & Run**
```bash
dotnet test                                   # run the full test suite
dotnet run --project src/NoaChess.GUI.Wpf    # play against the engine (Windows)
dotnet publish src/NoaChess.UCI -c Release -o out   # single-file UCI engine .exe
```
The published `NoaChess.UCI.exe` works in any UCI GUI (Arena, CuteChess, BanksiaGUI...).

### **Roadmap & Versions** (newest first)
- **v4.0.0** — **BLOCK 12 foundation. No Elo claim; the shipped net is unchanged and node counts are identical (193,746 on a fixed-depth suite, before and after).** New `nnueprofile` command measures where NNUE time goes: **L1 dot product 26.2%, feature-transformer row traffic 73.8%** — overturning the code's own two-version-old assertion that the dot product was "THE cost of NNUE eval", the claim that justified keeping the net narrow. **int8 L1 (architecture 2)**: evaluation 1039.9 → 774.7 ns (−25%), NPS 243.7k → 268.7k. QA must drop 255 → 127, a correctness bound rather than tuning: `VPMADDUBSW` sums two products into an int16 lane that saturates (255: 64,770 > 32,767; 127: 32,258 < 32,767), enforced by both loader and exporter. Architecture 1 remains fully supported and re-exports **byte-identically**; the embedded net stays arch 1 because QA=127 changes search enough (193,746 → 140,008 nodes) to require an SPRT. **Accumulator cache** ("finny table", keyed by king square because bucket-mates are mirrors with different orientation): refresh 4407 → 110 ns, 99.6% served from cache. **Accumulator updates** 1.9-2.5× faster in isolation after replacing bounds-checked `Vector<short>` loads — but **end-to-end wall time did not move**, because the real bottleneck is memory latency on a 5.5 MB feature table, not instruction count; reported as measured. **Streaming dataset** removes the 120M-record RAM ceiling (verified: 0 duplicates, 0 validation leakage, val 0.052585 vs in-RAM 0.052003). **Provenance gate**: `--require-book` and a mandatory `PROVENANCE:` line. Plus a pre-existing bug fixed that wrote checkpoints with `"model": None`. 222/222 tests.
- **v4.1.0 → v4.3.0 (PLANNED — the rest of the campaign)** — **NNUE architecture overhaul.** Diagnosis: gen3→gen7 landed flat (+4.5, +1.9, gen6 no promotion, +3.7) and deepening labels 24k→28k nodes bought +3.7 Elo — the signature of a **saturated network**, not exhausted data. The net is FT=128 with a single output bucket against reference-class FT=1024 with eight, trained on 13 M positions per generation against billions, with int16 L1 arithmetic against int8. The cost model that justified staying narrow does not survive arithmetic: at FT=128 the L1 dot product is ~512 AVX2 instructions per evaluation, far too small to be the bottleneck it is documented as — the real cost is feature-transformer row traffic and king-bucket refreshes, both fixable. **v4.0.0 Foundation** (no Elo claim): evaluation profile, int8 L1 on the AVX2 path, accumulator cache, streaming dataset replacing the 120 M-record RAM ceiling, machine-checked manifest provenance. **v4.1.0 Data scale**: labelling depth cut to 5–8k nodes, 300–500 M positions including elite WDL-anchored data. **v4.2.0 Capacity**: FT 128→512→1024 measured stepwise, 8 output buckets — the largest expected gain. **v4.3.0 Search**: complete correction histories, then the coupled search bundle measured as a bundle. Expected ~3080 → **3300–3450 CCRL**.
- **v3.4.0 (in progress — tooling only, no engine change)** — **Elite-data infrastructure.** Two data levers, after self-play depth, net size, lambda and search-threshold recalibration were all measured out. **Middlegame seeds** needed no code (`pgnbook` already had `--min-ply`/`--max-ply`): seeding self-play from ply 20-40 instead of 12-20, because the middlegame is where evaluation decides games. **Elite WDL anchoring** is new: `pgnbook --with-result` writes `FEN;R`, and `NoaChess.DataGen --label-book` labels positions real players reached with **(our own deep search score, their actual game result)** — no self-play. That outcome is the only signal in the pipeline the engine cannot manufacture for itself; self-play WDL is just its own evaluation played out, which is why the lambda sweep found it harmful. **Not imitation learning:** the human supplies neither an evaluation nor a move. Also `--skip-bots`, which drops games with `[WhiteTitle "BOT"]`/`[BlackTitle "BOT"]` — measured at **2.80%** of the corpus (151,328 of 5,397,639 games), and it matters because a bot game's result is another engine's opinion, not external information. The dataset format was unchanged (byte 32 already held the result); the manifest now records `mode` and `wdlSource` so an elite-labelled set can never be mistaken for self-play. 281/281 tests.
- **v3.3.0** — **Proven-mate stop. Strength-neutral (+3.3 ±23.1 over 523 games vs v3.2.1), shipped for the behaviour.** The iterative-deepening loop breaks once a completed iteration proves a mate in ≤3 plies for us, or that we are mated in ≤2 — the narrow case where deepening cannot improve the answer (reference rule, `search.cpp`). Long mates still deepen: the pre-existing "never break on mate scores" rule stays in force, because an earlier version of it made the engine walk into the shortest mate when losing. Measured at 5+5, same move and same reported mate every time: **mate-in-1 1074 ms → 22 ms** single-threaded, 1253 ms → 112 ms at 30 threads; normal midgame/opening identical in move, depth and score; fixed-depth byte-identical. The SPRT was stopped at LLR 0.03 rather than run to exhaustion — a ~0 Elo effect cannot converge, and its purpose (ruling out a regression) was met. **Also measured and CUT:** rescaling the NNUE output to align it with the classical margin scale. The mismatch is real (gen7 regresses on the classical evaluator at slope 0.783 over 6000 real positions), but correcting it scored −61.7 ±20.7 Elo, LOS 0.0%, H0 accepted — the pruning margins were already calibrated to the compressed net by the gen3–gen7 SPRTs, and inflating the eval makes RFP/razoring/futility fire far more often, producing unsound cutoffs. 281/281 tests.
- **v3.2.1** — **Bot-stability hot-patch. No evaluation change, no strength claim.** Diagnosed from a Lichess bot that stopped playing after a few games: the engine was NOT hanging (47+ games straight, 9-13/hour), the failure was resource oversubscription — with `Threads: 30` the process carries ~70 OS threads (ServerGC adds ~1 per core), starving lichess-bot's Python/network thread and the next game's engine startup (550 `protocol.initialize()` timeouts against a 60 s limit on 2026-07-29; 210 dropped connections on 07-30). Fixed on the bot side (`Threads` 30 → 24). Two real engine defects found on the way and fixed here: iteration depth was unbounded for ponder/infinite searches, so a repetition position with a warm TT spun through useless depths (22→26 in 30 ms) burning a core — now capped at `MaxPly`; and a stalled search froze the command loop with no trace — it now reports `info string search still stopping after Ns` every stalled second. 281/281 tests.

## Motor de ajedrez UCI en C# (.NET 10)

NoaChess es un motor de ajedrez UCI modular escrito desde cero en C# sobre .NET 10, con su propia GUI de tablero en WPF. Sigue un desarrollo incremental y medido: cada versión se valida con tests unitarios, Perft, matches automáticos entre motores y estimación de Elo antes de avanzar. El desarrollo está asistido por IA (Claude como herramienta de pair-programming); la arquitectura, la metodología de un término por SPRT, los gauntlets calibrados y cada decisión de aceptar o cortar un término son del autor.

**Versión actual: v3.2.0 — NNUE gen7 (NNUE-0.7) + pipeline de datagen con aperturas humanas.** El datagen de self-play siembra ahora las aperturas desde un libro humano de élite (chess.com >2800 + Lichess élite; 3,04M FENs únicos vía `pgnbook`) en vez de plies aleatorios. gen7 embebida, promocionada como generación **marginal**: **vs gen5 +3.7 ±10.2 (LOS 76.2%, paridad)**, **vs clásico +28.5 ±13.0 (LOS 100%)** — el valor NNUE acumulado total sobre el eval clásico. Gauntlet CCRL **57.9%, ~3080 ±40 CCRL** (gen5 daba 51,0% / ~3050; dentro del ruido). Sembrar con aperturas humanas **no** subió la fuerza sobre gen5 — la ganancia es el pipeline de datos (base para entrenar con datos de élite) y un +28.5 limpio vs clásico. Construida sobre el **Lazy SMP de v3.1.0 y la NNUE HalfKAv2_hm de v3.0.0**; incluye el fix de tiempo de v3.1.2. UCI `Threads` 1–32 (`Threads=1` byte-idéntico a v3.0.0). Ver [CHANGELOG](CHANGELOG.md).

### **Características principales**
- Representación por bitboards con **magic bitboards** para piezas deslizantes (lookup **PEXT/BMI2** en CPUs donde es rápido — Intel y AMD Zen3+ — con guarda automática por CPUID).
- Generación de movimientos legales completa (enroques, al paso, promociones), validada contra los valores públicos de referencia de Perft.
- **Búsqueda**: iterative deepening, aspiration windows con ensanchado progresivo, PVS, tabla de transposición (Zobrist), **generación de movimientos por etapas con legalidad perezosa** (jugada de TT servida sin generar, luego capturas, luego silenciosas), quiescence, null-move pruning, singular extensions, SEE para ordenación y poda, ordenación por killers/history/counter-move/continuation history, LMR logarítmico informado por historia, reverse futility pruning, futility pruning, late move pruning, Internal Iterative Reductions, ProbCut.
- **Búsqueda paralela (Lazy SMP)**: hasta 32 hilos worker buscan la misma raíz compartiendo una sola tabla de transposición lock-free (carreras benignas, verificadas por clave) y votan la jugada; el tablero, la pila de búsqueda, las historias y los acumuladores del evaluador son por hilo. `Threads=1` es byte-idéntico a la búsqueda de un solo hilo. Un guard de gestión de tiempo solo-SMP (instabilidad promediada sobre el pool, deadline soft acotado, cap a nivel de nodo a media iteración) acota un pico de reloj en ponderhit.
- **Evaluación**: evaluación tapered (fase media/final) mezclada por fase de juego — valores PeSTO, tablas pieza-casilla de dos fases, bitboards de ataque al estilo de referencia (attackedBy por tipo de pieza + dobles ataques) que alimentan una evaluación de amenazas completa (piezas colgadas, amenazas de menor/torre/rey, amenazas de peón seguro y de avance de peón, piezas restringidas, amenazas de caballo/deslizantes sobre la dama), seguridad del rey (unidades de ataque + escudo de peones mediante curva cuadrática), movilidad no-lineal de piezas (tablas lookup de referencia sobre un área de movilidad al estilo de referencia, con ataques x-ray y restricción de piezas clavadas), bonus de tempo, outposts de caballo, espacio, par de alfiles, torres en columnas abiertas/semiabiertas y en séptima fila, estructura de peones tapered (doblados/aislados/pasados/retrasados, peones en falange, pasados conectados, pasados bloqueados, torre detrás del pasado); término mop-up para finales ganados.
- **Evaluación NNUE**: red neuronal HalfKAv2_hm (InputSize 22528, reyes como features), pesos enteros cuantizados, acumuladores incrementales, inferencia SIMD AVX2; entrenada con datagen de self-play con mezcla WDL y adjudicación por resign/tablas, refinada por self-play generacional. Supera al evaluador clásico; seleccionable con las opciones UCI `UseNNUE` / `EvalFile`, con la red actual embebida en el ejecutable.
- **Gestión de tiempo**: presupuestos soft/hard, uso del 85% del incremento, horizonte adaptativo conservador por ply, soporte movestogo, márgenes de seguridad para la latencia de la GUI.
- **UCI completo**: uci, isready, ucinewgame, setoption (Hash, Threads, MoveOverhead, Profile, UseNNUE, EvalFile), position, go (depth/nodes/movetime/reloj/ponder/infinite), stop, quit. Búsqueda asíncrona; se publica como .exe único autocontenido.
- Perfiles de motor (Default/Bullet) con parámetros de búsqueda/tiempo ajustables.
- **GUI WPF** (MVVM): juega contra el motor con piezas vectoriales (SVG Cburnett), barra de evaluación y profundidad en vivo, análisis en segundo plano durante tu turno.
- Hot paths sin allocations; suite de benchmarks con BenchmarkDotNet.

### **Estructura de la solución**
```
src/NoaChess.Core      -> reglas puras: tablero, bitboards, movimientos, FEN, Zobrist
src/NoaChess.Engine    -> búsqueda, evaluación, heurísticas, TT, gestión de tiempo
src/NoaChess.UCI       -> host de consola UCI (el ejecutable del motor para GUIs)
src/NoaChess.GUI.Wpf   -> aplicación de tablero WPF (MVVM)
tests/                 -> suites xUnit (Perft, make/unmake, búsqueda, SEE...)
benchmarks/            -> micro-benchmarks BenchmarkDotNet
```
Regla de dependencias: `Core` no depende de nada; `Engine` usa `Core`; `UCI` y la GUI son hosts finos. El plan completo está en [ROADMAP.md](ROADMAP.md).

### **Compilar y ejecutar**
```bash
dotnet test                                   # suite de tests completa
dotnet run --project src/NoaChess.GUI.Wpf    # jugar contra el motor (Windows)
dotnet publish src/NoaChess.UCI -c Release -o out   # .exe UCI único autocontenido
```
El `NoaChess.UCI.exe` publicado funciona en cualquier GUI UCI (Arena, CuteChess, BanksiaGUI...).

- **v2.7.4** — **Rework de la quiescence: versión de corrección.** En jaque la búsqueda ya no hace stand-pat sobre un eval estático sin sentido (podía devolver un corte por beta *estando mateada*), genera **todas** las jugadas en vez de solo capturas (la única salida de un jaque suele ser un movimiento tranquilo de rey o una interposición), no poda nada y detecta mate. Cada captura que da jaque deja al rival exactamente en ese nodo, así que el agujero estaba en la línea principal de toda secuencia táctica — y ProbCut, las probes de null-move y multi-cut verifican capturas **a través** de la quiescence, con lo que estaban leyendo esas puntuaciones falsas como prueba. Añade guard de ahogado, puntuaciones fail-soft y las cuatro piezas de promoción; porta entero el bloque de poda de la referencia (margen de futility 147, umbral SEE relajado a −36, capturas ordenadas por una nueva tabla de **capture history** con updates por gravedad).
